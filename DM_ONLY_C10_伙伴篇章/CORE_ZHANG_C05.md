> **章内权威：** OPTION_ORDER_SEED、开场、关系核心、故事弧、角色信息、高理解回报、CG、低分收束、标题回收、固定真相、8节点职责、局部分流与公开收束。

- 关系阶段：关系后续章：本章为 `INVESTIGATION`；`ROMANCE_ACTIVE=true` 时呈现已成立情侣版本，否则呈现同等完整的亲密伙伴版本。本章不承担首次恋爱确认。
- OPTION_ORDER_SEED：`ACBCABCB`
- 开场：学院一场实战推演出现了两份互相矛盾、却都能自洽的优秀答案。评分表只认其中一种，负责老师请昀帮忙确认到底是哪边算错了。
- 关系核心：把昀的强逻辑真正用在一个需要更新模型的小调查里，同时让已成立的关系状态落在协作习惯上，而不是再讨论“要不要恋爱”。情侣版可以更自然地共享距离和默认信任；伙伴版同样是高强度、平等的双人推演。两版都禁止把林昭宁写成只负责夸他聪明的人。
- 固定戏剧弧：两份冲突答案→分别复核假设和推演过程→都找不到计算错误→回到题面发现缺失边界条件→确认两份答案在不同前提下都成立→修订评分说明→把“没有标准答案”从争谁对变成把条件说完整。
- 角色新信息：昀遇到“两个答案都能成立”时会本能想把隐藏条件找出来，但真正信任一个人以后，他不会要求对方先证明自己值得参与推演；他会直接把最容易出错的那一步交给对方检查，并认真消费对方指出的新条件。
- 关系分流：
  - `ROMANCE_ACTIVE=true`：情侣状态只改变已经成立的互动细节，例如他把自己正在看的那页直接移到你们两个人中间、你打断他时他不需要重新确认你的权限、长时间推演后会自然把杯子或椅子往你这边推；可以有短暂靠肩/手背碰到不急着避开等低调亲密，但不能把查题写成约会腔。
  - `ROMANCE_ACTIVE=false`：亲密伙伴版保持同等信任和共同推演，你一样可以直接改他的模型、拿他的笔、指出盲点；但不自动加入情侣专属身体亲密，也不把“没恋爱”写成缺失或遗憾。
- 高理解专属回报：在最终结论前，昀没有先给自己的版本，而是把题面、两份答案和笔一起推到你面前，说“你先写你觉得少了哪个条件。”等你写完，他才接着往下验证，不抢回主导权。
- 基础CG画面：桌上摊着两份解题纸和一张评分表，林昀弯腰站在桌边，一只手压着左边答案，另一只手用笔指着题面空白处。你站在他对面，桌中央还留着一块没有写字的位置。
- 高好感CG画面：两份答案并排摊开，林昀把自己的笔横放到你面前，又把题面转向你这一侧。你低头在空白处补写条件时，他的手停在纸边没有拿回去，视线跟着你的笔尖移动。
- 低分仍有戏：低分线里你们可以分别坚持不同答案更久，甚至一度把评分表拆得比题目还复杂；最终发现缺失条件后，昀会先看一眼满桌草稿，再很干地说“很好，我们证明了两个人可以一起把简单问题复杂化”，保留笑点而不损害关系。
- 标题回收：“没有标准答案”首先是本案技术事实——题面漏写边界条件时不存在唯一合法答案；结尾可以自然呼应两个人的协作方式，但禁止把调查结果硬解释成恋爱哲理。
- 固定真相：原题漏写一项决定资源上限的边界条件；两组分别采用了两个都合理的默认值，因此两套方案在各自前提下都计算正确。不存在作弊、改卷或故意误导。
- 固定四场：
  1. CHOICE01–02【问题限定 / 两份答案】：CHOICE01先限定目标是找出“冲突来自计算、假设还是评分规则”，不默认某组做错；CHOICE02只决定先复核哪一份答案或先看评分表，建立验证顺序。
  2. CHOICE03–04【推演复核 / 模型分歧】：CHOICE03处理你和昀怎样拆开检查步骤；当两份答案都暂时无错时，CHOICE04只决定下一步验证假设、题面或现场规则中的哪一层，允许两个人有真实分歧。
  3. CHOICE05–06【缺失条件 / 影响确认】：发现题面缺一项边界条件后，CHOICE05只处理怎样验证这是不是决定性因素；确认两组采用不同默认值后，CHOICE06处理怎样向老师和两组说明，而不是继续争谁更聪明。
  4. CHOICE07–08【把笔交给你 / 修订标准】：固定CG前CHOICE07处理昀把最关键的缺失条件交给你先写；CHOICE08只决定最终评分说明怎样修订，允许多个正确答案但要求前提写清。结尾消费进入本章时已有的 `ROMANCE_ACTIVE` 分流，不再追加关系确认事务。
- `ENDING_COOPERATIVE` 公开收束：答案没有被强行压成一个，缺失的条件被补回去了；你们也没有为了证明谁更会算，把一场复核变成输赢。
