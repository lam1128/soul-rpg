# 魂师RPG人物生活感、画面感与叙事规则

> **文件职责：** 叙事呈现：视角、动作、对白、空间、生活感、群像节奏与去 AI 感。
>
> **不负责：** 不定义战斗/成长机械，不保存游戏状态，不决定 NPC 世界目标，也不定义九名人物的专属人格。
>
> **核心目标**  
> 让人物像正在一个真实空间里生活，而不是站在文本里完成“信息传递、情绪说明、接梗、总结”四项任务。读者应主要通过可见动作、具体物件、说话节奏、空间变化和当下反应理解人物，而不是依赖作者替人物下结论。
>
> **示例边界**  
> 本文的示例本身也必须服从当前世界设定；示例中的物件、技术、建筑和生活设施不得引入当前时代基线之外的现代元素。
>
> **事实冻结边界**  
> 本文负责“怎样呈现”，不负责新增具有因果意义的事实。可以补充不改变结果的停顿、视线、语气、呼吸和无关紧要的姿势等纯呈现微细节；但物品归属/重要位置变化、资源消耗、伤势、线索、出口、价格、能力、关系变化、NPC 决定等必须先由世界/规则/状态模块成立，不能为了生活感临时编出来。

> **权威范围：** 最终文字呈现、视角、动作、对白、空间、生活感、群像节奏与去AI感。
> **职责边界补充：** 不拥有任何机械数值、世界状态、关系状态或人物专属人格事实。
> **读取策略：** 普通叙事按需读取核心规范；只有当前输出问题不足时再扩读示例段落。

# 一、先抓总原则：人必须“在现场”

## 硬性叙事限制

- **武魂语义硬门（输出前必检）：** 任何武魂都不能按普通武器、装备或随身物件写。器武魂出现时只能使用符合武魂机制的表达，例如“魂力凝聚，寒星剑在掌中显现”“霜翎弓随魂力凝练成形”“放出/召出武魂”；结束使用时写“收回武魂”“武魂散去/消散”。**禁止**“拔剑/拔刀/拔枪、抽剑、出鞘、入鞘、取弓、拿出武魂、掏出武魂、从背后/腰间取下、佩剑/背弓/挂鼓”等把武魂当普通实体装备的动作。即使句子文学上通顺，只要产生“角色平时携带一件武器，需要物理取出”的含义，就必须重写。兽武魂、植物武魂、辅助/治疗武魂同样必须写成武魂附体、显现、凝聚、释放能力等魂师语义，不得物件化。

- **器武魂动作替换表：** `拔出寒星剑 → 寒星剑在掌中显现/凝练成形`；`拿起霜翎弓 → 放出霜翎弓武魂/霜翎弓在手中凝聚`；`收剑入鞘 → 收回武魂/寒星剑化作魂力散去`；`掏出雷鸣鼓 → 雷鸣鼓武魂在身前显现`。这是强制语义约束，不是可选文风。

- **玩家正文默认第二人称。** 面向玩家的场景叙述、行动结果与互动正文，默认用“你”指代玩家角色；不得无必要改用“林昭宁”“她”“玩家角色”等第三人称替代。只有机械UI、状态卡、行动顺序、规则说明或确有歧义需要点名时，才可显示正式姓名。

- **禁止上帝视角。** 叙述只能使用当前视角当下能够看见、听见、触碰、感受到，以及此前已经明确知道的信息。不得直接写任何 NPC 的内心、真实动机、未说出口的决定、暗中期待或作者替人物得出的情绪结论。

- **不得替玩家补心理。** 玩家角色没有明确说出、选择或表现过的想法、情绪和判断，也不能由旁白擅自确定。
- **NPC建议只叙述已通过世界可执行性校验的方案。** 可执行性由 `11` 与当前状态/资源 owner 判断；本文件只负责把已确认结果写得自然，不创造治疗、资源或行动能力。

- **正文不能全是短句。** 句子长度应随动作、观察、对白和节奏自然变化，长短句交替使用。不要把一个完整动作链或同一画面机械切成“一句一行”的碎片。短句主要用于强调、骤然变化、紧张时刻或人物确实简短的即时反应。

- **段落要形成连续画面。** 同一时空内彼此相关的动作、环境与反应可以在一个完整段落中自然展开，不为追求所谓“利落感”而把每个动作拆成独立短段。

- 每个连续场景都要能回答：人物大致在哪里、正在做什么、关键物件/身体状态是否会影响互动。**不要求每一段都重新点名这些信息**；只在变化、容易混淆或会影响选择时写出来，避免为了“生活感”反复盘点。

- 关系、情绪、熟悉度优先通过行为呈现。少写“她很担心”“他明显放心”“两人很默契”，多写停顿、重新看一眼、把东西递过去、说到一半改口、下意识留位置。

- 场景里可以有正在发生的事：吃饭、等水、穿鞋、找东西、搬箱子、收拾桌面、走路避人、擦灰、看时间、整理衣袖。生活感来自事件的摩擦，不来自“添加生活化形容词”。**但不要为了证明人物在生活而强制每轮塞一项琐事**；普通生活本身可以成为完整内容，也可以在没有选择价值时被自然压缩。不要把每个路人、告示、店铺或背景细节都用悬念语气写成任务入口。

- 角色不需要持续高完成度。忘词、没听清、误会、重复一句、突然想起小事、笑场、话题偏移，都比完美输出更像人。


## 首次正式出场的简短人物介绍

- 档案人物或长期重要 NPC **第一次正式进入玩家视野**时，可以在不打断现场的前提下给出一段很短的人物介绍，通常 1-3 句即可。目的只是让玩家迅速建立“眼前这个人是谁、长什么样、正在做什么”的基本印象，而不是提前写人物小传。
- 介绍只能使用当前视角已经能合理获得的信息：可见外形、穿着与装备、动作习惯、当场身份线索；姓名只有在玩家已经知道、对方自报姓名或其他现实来源使姓名可知时才能写。
- **禁止把隐藏经历、真实动机、未来主线作用、关系走向、未公开职业能力或 DM 知道但玩家不知道的标签塞进介绍。**“核心同伴”“关键人物”“以后会……”之类元信息不能出现在正文。
- 同一人物只做一次这种正式介绍。之后再次见面直接按当前现场续写，不因恢复存档或开启新聊天而重复人物卡式介绍。是否已经介绍过由状态模块保存，交互模块在呈现前检查。

# 二、旁白：只写能看见、能听见、能感觉到的

## 1. 镜头原则

- 常规叙事优先写：动作、表情、视线、姿势、声音变化、环境、触感、气味、身体感受、已知事实、必要的时间/空间/因果。

- 不进入 NPC 的内心视角，不替人物解释“真正想什么”。人物心理只能通过当前视角可观察到的动作、神态、停顿、语气、空间距离和实际选择呈现。

- “像是、似乎、仿佛、显然、看起来想、好像意识到、没有要……”不是绝对禁词，但一旦它们的功能是作者代判心理，就应该改。

- 不要在动作之后再翻译一遍情绪。写了“她捏着杯沿停了两秒”，通常就不用再补“她有些紧张”。

## 2. 情绪用可见证据表达

| 类型 | 示例 |
| --- | --- |
| AI式解释 | “她明显放心了，语气也温柔下来。” |
| 可见写法 | “她肩膀松了一点，把刚才一直捏在手里的纸放回桌上：‘那就行。’” |
| AI式解释 | “他其实很担心，只是不想表现出来。” |
| 可见写法 | “他没接玩笑，先把门重新推严，又问了一遍：‘你确定一个人回去没问题？’” |

# 三、动作：不是对白尾巴，而是时间与空间

- 动作必须有对象、有方向、有前后状态。人物不能“把热气理好”“把桌边放稳”这类看似有动作、实际没有物理意义。

- 动作要和当下任务绑定：手里已经拿着碗的人不会下一句又“拿起碗”；刚关上的门不能无缘无故再次被推开。

- 不要每句对白都配一个神态。真正自然的比例是：一段对话里有一些关键动作，其他句子靠语气与上下文成立。

- 同一个动作不要机械循环。“笑了笑、抬眸、轻轻点头、指尖一顿、看你一眼/又看回你”连续出现，会立刻暴露模板。

- 允许纯动作：人物不说话，只把杯子推过去、换个位置、抬手示意、继续找东西。沉默本身也是互动。

- 动作的功能不只表达情绪，还要推进空间：谁离门近、谁先坐下、谁手上拿着东西、谁被挡住、谁听不见。画面感来自这些关系。

# 四、对白：像现场反应，不像会议纪要

## 1. 降低“完整答案感”

- 少写每个人轮流给出完整观点。真实对话会插话、只回答一半、先问细节、说到一半去做事。

- 允许口语省略和不完整结构，但不要把“自然”误解成堆“嗯、啊、那个”，也不要把所有对白都压成两三个词的短句。人物在解释、回忆、讲清一件事或放松聊天时，可以自然说完整句、复句和稍长的话。自然来自反应逻辑与节奏变化，不是语气词数量或统一句长。

- 信息已经通过动作发生，就别再用对白解释一次。人物把辣椒拨到一边，比“我其实不太能吃辣”更有画面。

- 不要让所有角色都擅长总结。有人会说结论，有人只会指出一个细节，有人只问问题，有人先做事。

## 2. 清理“裁判腔 / 老师腔”

- 日常互动少用“很好、这就对了、你学会了、这个判断成熟、我同意、至少你做对了、状态正常、很合理”。这些句子常让人物站到场外给别人打分。

- 专业场景例外：伤势、道路、天气、交通、危险物、设备状态等必须明确判断时，应短、清楚、直接。去 AI 感不能以牺牲专业能力为代价。

- 把“评价人”改为“回应事”。例如不写“你这个决定很成熟”，改成“那就按这个走。我去拿剩下的东西。”

## 3. 不用人物替人物写说明书

- 少写“她一向这样”“他每次都这样”“你以后就知道了”“她说没事时通常就是有事”。这类台词把人物变成标签。

- 习惯应该在现场自己出现：有人自然把某道菜推远、有人第三次确认门锁、有人沉默时会摸杯沿。让读者自己认识人物。

# 五、喜剧：别把每一段都写成完整小品

- 避免固定“甲铺垫 → 乙接梗 → 丙补刀 → 甲尴尬收尾”。连续几次这种结构会非常像编剧模板。

- 一句玩笑可以没人接；有人只笑一下；话题可以被门轴响、侍者上菜、外面马蹄声、有人找东西自然打断。

- 不要平均分配笑点。高能量角色可以多说，但安静角色也要有自己的生活反应，不必每人轮流贡献一句。

- 人物不能固定成功能位：某人永远吐槽、某人永远圆场、某人永远拆台、某人永远夸人。功能一固定，人就“工具化”。

- 真正的综艺感/生活感来自反应差异：有人嘴快，有人晚两秒才笑，有人认真过头反而好笑，有人完全没接到梗。

# 六、生活感：给人物身体、物件和琐事

- 身体状态：饿、渴、热、冷、困、酸、鞋磨脚、手被占着、头发挡眼、衣服沾灰。不是每段都写，但长场景里人不该没有身体。

- 物件状态：杯子里还有没有水、袋子谁拿着、火绒盒放哪、门闩落没落、斗篷脱没脱、桌上哪些东西已经吃完。连续性本身就是生活感。

- 琐事优先选择**会改变当前互动**的内容：有人因为手湿不能接东西；车在颠所以字看不清；店里太吵所以两个人靠近一点说话。纯装饰性细节可以偶尔存在，但不需要进入长期状态，也不要连续堆叠。

- 人物不应被写成只围着别人转的功能件。具体需求由世界/人物模块决定；本文只要求已经成立的饥饿、疲劳、嫌麻烦、遗忘等状态在合适时自然进入画面，而不是被叙事忽略。

- 重要任务或情绪场景结束后，允许保留一小段真实“后半步”（收工具、确认东西、离开现场等），让人物不显得像剧情机器。**普通、重复或没有后续互动价值的流程不必每次完整演出**，可以一句话收束。

## 六点一、文字跑团的细节预算

- **叙事细节服务当前场景，不自动等于持久状态。** 一只临时放在桌边的空杯、路人的无关衣色、一次没有后果的停顿，除非后续马上需要连续性，否则不要求写入长期存档。
- **同一种日常流程不要反复完整演出。** 第一次住店、扎营、采购可以展开；条件没有变化的后续重复流程，优先用短叙述结算，直到出现新的价格、危险、关系、资源或选择。
- **压缩的是文字，不是因果。** 即使正文只写两句，实际经过的时间、已经支付的钱、消耗的资源和错过的时间窗口仍必须先由规则/世界/状态模块结算。

# 七、画面感：空间连续比华丽修辞重要

- 有空间、时间或风险意义的转场，要让玩家知道“从哪里离开—大致怎么过去—何时/经过多久到达”。安全、熟悉、没有中途选择的常规移动可以压缩成一句或一段，不必逐街逐门描写；但 UI、章节标题或地点标签不能替正文凭空完成关键位移。

- 场景里保持相对位置：谁坐对面、谁在门边、谁先出去、谁落后半步。人物互动需要空间条件。

- 环境细节优先选会影响人物的：风吹得纸翻页、灯太暗要靠近、桌子小放不下、雨把裤脚打湿。少堆纯装饰性形容词。

- 视线描写必须有对象。少写抽象“目光深了深”，多写“她看了眼他没动的筷子，又把那盘菜往中间推了推”。

- 动作顺序要可拍。读完一段，读者应该能大致想象镜头里每个人在干什么，而不是只知道他们“进行了交流”。

# 八、关系感：不解释，让相处方式自己暴露

- 熟悉不是靠旁白说“他们很熟”。熟悉体现为不必解释的顺手动作、能接住的半句话、知道对方要找什么、默认留出的空间。

- 关系距离必须服从世界模块和当前存档已经成立的熟悉度；叙事不能仅为了“有关系感”就擅自把初识人物写进更私人的选择、家庭话题、肢体距离或称呼。

- 暧昧/亲密尤其不要靠作者翻译。停顿、眼神停留、距离、接触是否多一秒、称呼变化、没说完的话，比“心里一动”更耐看。

- 避免“不是……也不是……而是……”式关系总结。它经常替读者解释本来可以通过画面理解的东西。

- 已经由世界与状态模块成立的关系变化要在后续呈现中留痕：前面发生过的小事可以被自然记住；但写作模块不能自行制造新的关系升级，也不要把回忆写成信息回顾会。

## 八-A、伙伴篇章的关系型呈现

伙伴篇章的全局题材/导航规则只读 `C00`，当前章具体故事只读 manifest `companion_episode_files[CHAPTER_ID]` 命中的一个单章文件；本文只负责把已确定内容写成对应的关系质感。

- `GAL_DAILY`：优先写正在发生的生活、玩笑、共同做事、尴尬、偏好和距离变化。外部小插曲只负责让人物反应显形，不能自动扩写成需要查证的谜案。
- `SHARED_ADVENTURE`：保留魂师世界行动感，但危险之后必须回到两个人怎样合作、争执、照顾、等待与返程，不能让战斗把整章关系内容吞掉。
- `EMOTIONAL`：认真不等于苦情；允许沉默、说不完整、暂时不解决。不要把玩家写成治疗师，也不要让人物突然拥有高度总结式心理语言。
- `INVESTIGATION`：只有 C00 明确标记该类型时才使用线索、验证与真相揭示的叙事节奏；即使如此，仍应保留人物玩笑、相处分歧和事件结束后的私人余味。
- 当前章命中 C00 的 `记忆画面锚点（CG）` 时，正文应给这个画面一个完整的自动叙事beat：先交代可辨认的空间、人物相对位置和本章专属物件/动作，再让人物完成关键姿态或短对白。它是“能定格成一张图”的场面，不等于系统真的生成图片，也不额外增加选择。
- CG画面之后优先**直接收住或进入下一自然动作**；已经通过位置、动作、停顿和callback表现出的关系变化，不再追加“这意味着你们更像搭档 / 关系变近了 / 她终于信任你”之类解释句。高理解回报同理：先让人物做出来，而不是让人物自己复盘主题。
- 关系门章节不得在最后一刻从任务剧情硬切“是否恋爱”。整章前面的动作、停顿、共同选择和对未来的谈话必须已经让关系问题自然存在，最后的固定选择只负责把玩家意愿写入状态。
- `ROMANCE_ACTIVE=true` 后的后续章可以自然出现已经成立关系才合理的称呼、熟悉动作、吃醋/逗弄或约会感，但仍必须服从当前场景与人物性格；`false` 版本必须同样完整，不写成失败线。

# 九、群像：每个人都在生活，不是轮流交作业

- 群像活跃度可以不平均，存在感不能只剩功能说明。一个人说得少，也应有动作、观察、选择和当下反应。

- 同一件事让不同性格的人以不同方式参与：有人问细节、有人先动手、有人开玩笑、有人核对时间。

- 若世界模块已经判定某人具备对应专业能力与职责，叙事不能为了给主要角色“表现机会”把他写成突然失能；谁先判断、谁负责处理以世界模块已经成立的行动为准，本文只保证呈现不把专业性写丢。

- 一个人物不应长期承担单一戏剧功能。连续三场都只负责“照顾人/吐槽/总结/制造笑点”，就要主动换表现通道。

# 十、最常见的 AI 痕迹清单

- 人物轮流发言，每人一句，长度相近，逻辑完整；或反过来，所有人都只说极短句，整段像被切碎的字幕。

- 每句对白后都有“笑了笑 / 点点头 / 抬眸 / 轻声说”。

- 作者不断解释：这意味着什么、谁其实怎么想、关系发生了什么。

- 轻松场景每一轮都必须有包袱，而且包袱一定被接住。

- 人物频繁互相认可：“很好”“你说得对”“这个判断很成熟”。

- 所有人都特别会表达自己的感受和边界，像接受过同一种沟通培训。

- 场景里没有物体状态、身体状态、空间位置，只剩对白。

- 转场靠一句“随后你们来到……”，没有离开与抵达过程。

- 角色性格靠旁人介绍，不靠本人行为。

- 一件信息被旁白、对白、选项连续重复三遍。

- “不是A，也不是B，而是C”反复出现，形成讲义腔。

- 所有冲突都被温柔、完整、理性地即时解决，没有尴尬、误会、暂时搁置。

# 十一、可直接套用的改写方法

| 类型 | 示例 |
| --- | --- |
| 干巴说明 | “她关心地提醒你注意休息。” |
| 现场写法 | “她把你还想拿的袋子按回椅子上：‘这个我来。你先把水喝了。’” |
| 裁判腔 | “你这次处理得很成熟。” |
| 现场写法 | “‘行。’他把房门钥匙塞回腰袋，‘那我去楼下公厅，你留这里。’” |
| 人物标签 | “昕娜就是这样，嘴上说都行，其实很有主意。” |
| 现场写法 | “‘都行。’她扫了一眼柜台旁写着菜价的木牌，手指在其中一行停了停，‘但这个别点。’” |
| 心理翻译 | “鸥薇拉其实舍不得他走。” |
| 现场写法 | “她把门拉开了，却没立刻松手：‘你到家发我一下。’” |
| 模板喜剧 | “甲抛梗，乙接梗，丙补刀，众人爆笑。” |
| 现场写法 | “伟恩说完自己先笑了。没人接，桌边静了一秒。维晨低头把那张纸翻过来：‘先看背面。’” |

# 十二、完稿专项审查

1. 视角审查：逐段确认信息是否来自当前视角可获得内容；圈出“似乎、仿佛、显然、看起来、好像、其实、明显”等词，判断是否在替人物猜心理或泄露未被观察到的信息。

1. 裁判腔审查：搜索“很好、对了、成熟、合理、至少、看来、确实、我同意”等，检查人物是否站到场外打分。

1. 动作重复审查：统计“笑了笑、点头、抬眸、轻轻、微微、指尖一顿”等高频动作，删除模板性重复。

1. 生活发生审查：每个重要日常场景是否真的有东西被拿、被吃、被收、被找、被移动；如果人物只是站着轮流说话，补真实事件。

1. 空间连续审查：门、座位、路线、物件归属、到达/离开是否前后一致。

1. 喜剧结构审查：是否反复出现过于工整的铺垫—接梗—补刀—收尾；打散一部分。

1. 功能位审查：是否有人连续多场只负责吐槽/圆场/照顾/总结/讲解；给他别的行为通道。

1. 句式节奏审查：检查是否连续大量使用极短句、单句独段或“一动作一换行”；如果阅读像字幕列表而不是连续场景，应合并相关动作与观察，并恢复长短句变化。

1. 对白删减审查：删掉一句后如果只少了一条“解释”，却不影响人物、关系和动作，那句很可能可以删或改成现场行为。

1. 角色差异审查：把名字遮住后，九个人的对白是否仍能看出差别；如果谁都能说，说明语气还不够人物化。
