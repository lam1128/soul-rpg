# 魂师修炼RPG｜专用项目入口协议

> **文件职责：** 定义部署到 ChatGPT 专用项目时，最外层项目指令应承担的最小启动壳职责。
>
> **权威范围：** Git-only 项目入口发现、治理入口转交、项目文件候选池接入。
>
> **不负责：** 不复制业务规则、route 表、checkpoint import 排序算法或动态状态值。
>
> **读取策略：** 仅部署/项目维护时读取；普通游戏轮不常驻。

## 1. 项目外层只负责找到当前 Git 权威入口

固定入口：

`main HEAD`
→ `governance/project.md`
→ `runtime/registry.json`
→ 当前 dispatcher。

不存在 compatibility runtime ZIP fallback，也不得把任何旧运行包、旧 manifest 或聊天历史副本当成替代入口。

项目外层不得要求“开始/恢复/继续前全文读取全部权威文件”，也不得复制战斗、世界、人物、经济、UI、存档 schema 或 route 实现。

## 2. Git current state 与外部 checkpoint 候选池

当前冒险直接从 registry 登记的 `state_model.current_state_owner` 恢复；用户不需要为了“继续游戏”反复上传同一存档。

专用项目里额外存在的合法 checkpoint 只作为 `external_sources.checkpoint_import` 的显式导入/恢复候选。候选合法性、选择顺序、冲突处理与迁移边界只认当前 registry 与 `rules/12_状态存档.md`，本文件不维护第二套算法。

## 3. 状态边界

项目外层不得直接修改 checkpoint、重建工作态、写 `state/current` 或提高 `STATE_REV`。普通运行候选由业务 route/`12` 校验后交给 `STATE_COMMIT`；外部 checkpoint 导入、便携导出与迁移由 registry 当前登记的 Skill 执行。外层项目不得复制其实现。

## 4. 项目外层禁止复制业务

项目自定义指令只保留“解析当前 Git 入口 → 进入治理入口”的壳层要求。其余内容一律从当前 registry 动态解析。

## 5. Skill 依赖边界

`control_intents` 中 `dispatch_type=skill` 的条目是外部 Skill 依赖的唯一机器登记：只保存 Skill 名称与 operation 指针，不另维护 Skill 清单。专用项目必须安装这些依赖；若缺失，相关事务失败关闭并提示安装。项目指令不得复制 Skill 工作流，也不得恢复已删除的同职责 route。
